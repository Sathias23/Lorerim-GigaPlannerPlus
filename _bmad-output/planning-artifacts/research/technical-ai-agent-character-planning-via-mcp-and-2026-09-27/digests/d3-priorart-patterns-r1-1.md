## Direct answers

**Q1 Prior art.** Build-planner MCPs exist and are active for Path of Exile 1 and 2, but for no other game I checked. The strongest pattern (pob-mcp) wraps the game's real calculation engine headlessly. It exposes three kinds of tools:
- fine-grained read and mutate tools (set tree, add gem, set config)
- engine-driven search tools that enumerate candidates, simulate each and return a ranked list (optimize_tree, find_best_anointment, suggest_masteries)
- a validator that returns severity-tagged findings (findings 1–2)

poe2-mcp adds a game-file-extracted database with inspect/list/search lookups, name binding, and fail-loud checks for data drift (4). I found no user reports that measure build quality from any of them, only READMEs (5). No Skyrim, LoreRim or other Bethesda character-build MCP exists in what I found; the Skyrim MCPs cover mod authoring, diagnostics and live-game control (7). That makes the LoreRim planner MCP apparently novel. The closest template is pob-mcp.

**Q2 Generate–validate–repair.** It works, but mainly because the feedback is external and deterministic. Self-critique without it does not reliably help (11). On TravelPlanner, a propose-and-critique loop with up to 10 back-prompts gave a 4.6x lift, yet only reached 20.6% (8). Feedback helped more when it covered every class of violation together, not one critic type at a time (8). The 10-iteration cap is the only iteration figure I retrieved; I found no distribution of how many rounds it takes to converge. Useful feedback, from what the sources imply:
- report all violations at once
- make them machine-specific (the entity, the constraint, by how much)
- never drop invalid input silently — pob-mcp's silently dropped disconnected nodes are an anti-pattern (3)

**Q3 Hybrid LLM + solver.** The evidence clearly favours delegating. Letting an LLM formulate the problem while a solver searches reached 93.9%, against 20.6% for an LLM proposing inside a critic loop and about 10% for direct planning (8, 9). When LLMs optimize directly, the failure is mostly feasibility (65% at best); objective quality is decent once a solution is feasible (10). Their typical errors are the ones a perk-budget planner would hit: small budget overshoots, ignored secondary constraints, and invented entities (10). So:
- let the TS engine, or a search or solver over it, own feasibility and "maximize X under budget"
- let the LLM translate the user's intent into goals and weights, and choose among engine-ranked options

This is the pattern pob-mcp already uses (2).

**Q4 Grounding.** The evidence here is thin. poe2-mcp binds every name against a local DB with inspect/list/search tools and fails loudly on unknown entries (4). ConstraintBench shows that entity hallucination is a real, measurable failure class when models work unaided (691 violations; 10). I retrieved no measured comparison of the three techniques: enum-constrained schemas, search-then-select, and "did you mean" close-match errors. With hundreds of perks, enum schemas are probably impractical and search-then-select plus strict id validation is the natural fit, but that is **unverified belief**.

**Q5 Judging "good" builds.** LLM judges are consistent but not necessarily valid. Human agreement is moderate (κ about 0.3–0.5 on open-ended preference tasks), position bias persists, and rankings do not transfer across benchmarks (12). Rubric wording and co-graded items can shift scores (13, low confidence). Recommended design:
- explicit engine-computed scoring for anything measurable (damage proxies, defensive layers, budget use), as pob-mcp does with DPS/EHP deltas and a 0–10 health score (2)
- a rubric LLM judge only for qualitative fit to the user's intent ("feels like a stealth vampire archer"), judged pairwise with position swaps (12)

## Leads (contradictions first)

- **Contradiction or tension:** two TravelPlanner results imply that LLM plus critic loops plateau low (20.6%) while LLM-to-solver formulation succeeds (93.9%). Different models and setups were used, so a controlled comparison is still needed. Also check the Sept 2026 paper "Replan, Repair, or Edit?" (https://arxiv.org/pdf/2609.19654), which evaluates repair strategies directly. It is very fresh and I did not read it.
- The LLM-Modulo compound-systems paper (https://yochan-lab.github.io/papers/files/papers/compound-systems-final.pdf) may have per-iteration convergence curves and guidance on the format of critic feedback.
- Read pob-mcp's issues, PRs and any Reddit /r/pathofexile or /r/PathOfExileBuilds threads for real user outcomes. Also check pob-mcp's commit dates, which I did not confirm.
- "Formalize, Don't Optimize: The Heuristic Trap in LLM-Generated Combinatorial Solvers" (https://arxiv.org/html/2605.12421v1) is relevant to whether the LLM should write search code or call a fixed optimizer tool.
- NLCO benchmark (https://arxiv.org/html/2602.02188): LLMs on natural-language knapsack-style tasks, a close analogue of point-budget allocation.
- SkryimMCM exposes live player stats at runtime; it could in principle cross-check a planned build in-game.

## Gaps

- **No Skyrim, LoreRim, UESP, Diablo IV, Last Epoch, BG3 or Elden Ring build-planner MCP found.** The Last Epoch search returned only web planners. I did not search D4, BG3 or Elden Ring individually because of the budget, so their absence is only partly checked.
- No quantitative or user-reported outcomes for any game-build MCP; only READMEs.
- No measured comparison of grounding techniques (enum schemas vs search-then-select vs close-match suggestions), and no tool-use hallucination benchmark was retrieved.
- No data on the typical distribution of repair iterations beyond LLM-Modulo's cap of 10.
- No study on scoring game builds specifically, or other creative designs under constraints.
- Freshness: the pob-mcp and poe2-mcp README states have no confirmed dates, so treat the prior-art details as **possibly stale**. All research findings are within 2 years except the survey, whose v3 is 2024-12, which is within the bar.
